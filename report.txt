1. RINGKASAN EKSEKUTIF (EXECUTIVE SUMMARY)
--------------------------------------------------------------------------------
Proyek ini bertujuan untuk memperbarui dan memodernisasi Ekstensi Metode 
Pembayaran Purchase Order (PO) dari arsitektur terdahulu (OpenCart 3.x / PHP 7.x) 
agar sepenuhnya kompatibel dengan OpenCart versi 4.x dan versi PHP terbaru (PHP 8.0 
hingga PHP 8.4).

Seluruh kode telah direstrukturisasi mengikuti standar PSR-4 Namespace, arsitektur 
event/route OpenCart 4, pengaman sintaks ketat (Strict Typing), sanitasi input 
pengguna, serta tampilan antarmuka Bootstrap 5 terbaru. Ekstensi ini juga telah 
dikemas ke dalam format terkompresi `.ocmod.zip` agar dapat langsung diunggah melalui 
Extension Installer OpenCart 4.

2. DAFTAR PERUBAHAN UTAMA (SUMMARY OF CHANGES)
--------------------------------------------------------------------------------

A. ARSITEKTUR & KOMPATIBILITAS OPENCART 4
--------------------------------------------------------------------------------
1. Restrukturisasi Folder Ekstensi (OC4 Package Standard):
   - Menyelaraskan struktur folder internal ke dalam `extension/purchase_order/` 
     (termasuk direktori `admin/` dan `catalog/`).
   - Penambahan file manifest `install.json` versi 4.0.0.0 sebagai identitas 
     resmi modul pada Extension Installer OpenCart 4.

2. Penerapan Namespace PSR-4:
   - Penggunaan namespace resmi OpenCart 4 pada seluruh Controller dan Model:
     * `Opencart\Admin\Controller\Extension\PurchaseOrder\Payment\PurchaseOrder`
     * `Opencart\Catalog\Controller\Extension\PurchaseOrder\Payment\PurchaseOrder`
     * `Opencart\Catalog\Model\Extension\PurchaseOrder\Payment\PurchaseOrder`

3. Penyesuaian Routing & Endpoint AJAX:
   - Pembaruan mekanisme pemanggilan AJAX pada OpenCart 4 yang menggunakan 
     karakter Pipe (`|`) sebagai pemisah action, contoh:
     `index.php?route=extension/purchase_order/payment/purchase_order|confirm`
   - Pemisahan logika simpan konfigurasi di admin menggunakan method AJAX `save()` 
     yang mengembalikan respons berformat JSON (`$json['success']` / `$json['error']`).

4. Konvensi Prefix Konfigurasi:
   - Mengubah seluruh kunci pengaturan dari format lama menjadi berawalan 
     `payment_purchase_order_*` (contoh: `payment_purchase_order_status`, 
     `payment_purchase_order_required`, `payment_purchase_order_total`).

5. Dukungan Simpan Data Order & API Checkout OpenCart 4:
   - Menyediakan return array standar pada `getMethods()` yang mendukung struktur 
     `option_data` OpenCart 4.
   - Tetap menyediakan fungsi fallback `getMethod()` untuk fleksibilitas 
     backward compatibility.
   - Menyimpan informasi metode pembayaran di database `order` dengan format JSON 
     yang diwajibkan oleh OpenCart 4:
     `{"name": "Purchase Order (#PO-2026-001)", "code": "purchase_order.purchase_order"}`
   - Menambahkan method lifecycle `install()` dan `uninstall()` untuk menginisialisasi 
     dan menghapus konfigurasi default secara bersih dari database.


B. PEMBARUAN SINTAKS & TIPE DATA PHP 8.x / PHP 8.4
--------------------------------------------------------------------------------
1. Strict Type Header:
   - Penambahan `declare(strict_types=1);` di setiap file kode PHP untuk menjamin 
     eksekusi kode yang aman dan mencegah tipe data implisit (type juggling).

2. Return Type Hinting & Parameter Type Hinting:
   - Penambahan type hinting eksplisit pada parameter dan return value fungsi, 
     seperti `: void`, `: string`, `: array`, `array $address = []`, `float $total = 0`.

3. Operator Modern PHP 8 (Null Coalescing & Strict Comparisons):
   - Penggunaan Null Coalescing Operator (`??`) untuk menghindari error undefined index:
     `$address['country_id'] ?? 0`, `$this->request->post['po_number'] ?? ''`.
   - Penggunaan pencocokan tipe ketat (Strict Comparison) pada `in_array(..., true)` 
     dan `===`.

4. Typed Property Declarations:
   - Deklarasi properti kelas dengan tipe spesifik, contoh: `private array $error = [];`.


C. FITUR BARU, KEAMANAN, DAN VALIDASI INPUT
--------------------------------------------------------------------------------
1. Pengaturan PO Required (Wajib / Opsional):
   - Opsi konfigurasi baru di Admin untuk menentukan apakah Nomor PO wajib diisi 
     oleh pelanggan saat checkout atau opsional.

2. Pembatasan Customer Group (B2B / Wholesale Restriction):
   - Fitur untuk membatasi akses pembayaran Purchase Order hanya bagi kelompok 
     pelanggan tertentu (misalnya pelanggan Grosir/B2B), sesuai dengan tipe bisnis PO.

3. Sanitasi & Sanitization Input Nomor PO:
   - Validasi Regex (`preg_match('/^[0-9a-zA-Z\-\/\_\.\#\:\s]+$/', $po_number)`) 
     untuk memastikan Nomor PO hanya berisi karakter alfanumerik dan simbol aman.
   - Sanitasi string dengan `trim()` dan `strip_tags()` untuk mencegah serangan XSS 
     (Cross-Site Scripting) dan penyelewengan input.


D. DESAIN ANTARMUKA & PENGALAMAN PENGGUNA (UI/UX)
